# v0.3.3 验证记录

本记录对应 0.3.3（build 8）。验证环境为 macOS arm64、Apple Swift 6.1.2；结果来自本地自动测试，没有将自动测试等同于真实双机长期使用测试。

## 自动测试与构建

`swift test -j 2`：41 个测试全部通过，最终日志没有编译警告。

测试覆盖以下行为：

- 协议分片解码、16 KiB 单帧上限、256 条队列上限和一次处理任务预约。
- 消费暂停时的事件积压、断线后旧批次失效。
- 本机回环 TCP 中的远端关闭、错误配对返回后关闭、握手超时和最终帧发送。
- helloAck v1/v2 兼容、反复跨屏返回及重复 release 去重。
- 普通键和左右修饰键释放、Caps Lock、物理按键快照与重连后的过期状态清理。
- 恢复本机后对旧输入重复、拖拽和松开事件的抑制。
- 双击、右键拖拽、异常按钮及键码、非有限移动值和超大滚轮值。
- 光标固定位置和本机相邻显示器的共享边缘判断。

输入测试使用内存中的事件回调，不会向系统发布真实键鼠事件。网络测试客户端只连接 `127.0.0.1`，不会接管另一台 Mac；测试监听器会短暂监听本机接口，`ReceiverServiceTests` 还会发布 Bonjour 服务。请在允许局域网服务发现的测试环境中运行。

`zsh scripts/build-app.sh release`：构建成功，产物通过 `codesign --verify --deep --strict`。发布的安装包为 arm64，采用临时签名，未经过 Apple 公证。

## 事件积压的内存检查

复现命令：

```bash
swiftc -O Sources/ThunderLink/WireMessage.swift Sources/ThunderLink/OutboundMessageQueue.swift Tools/MemoryProbe.swift -o /tmp/thunderlink-memory-probe
/tmp/thunderlink-memory-probe
```

检查故意暂停消费，并提交 100 万个模拟按键事件。实测结果：

| 指标 | 结果 |
| --- | ---: |
| 队列峰值 | 256 条 |
| 处理任务预约 | 1 次 |
| 溢出通知 | 1 次 |
| 第 10 万个事件时进程峰值常驻内存 | 2,605,056 字节 |
| 第 100 万个事件时进程峰值常驻内存 | 2,621,440 字节 |
| 后 90 万个事件增加的峰值常驻内存 | 16,384 字节 |

具体内存读数会因工具链和环境变化。此检查验证有界队列机制，不能用于推断完整 App 的长期内存占用。
